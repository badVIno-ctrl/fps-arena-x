# Что доделать

Состояние на `c6c1407`: дерево чистое, 12/12 гейтов зелёные (`npm test`), игра
запускается, боты не убивают на спавне, доска оружия не морозит матч.

---

## Инструмент, с которого надо начинать

`tools/lab.mjs` — живой стенд. Он поднимает статическую сборку, открывает
настоящую игру в настоящем WebGL2 и даёт прогонять произвольный код против
работающего движка. **Без него почти ничего из этой сессии нельзя было бы ни
найти, ни проверить.**

```bash
pnpm build
node tools/lab.mjs eval --script=tools/lab/sheet.mjs      # оружие в профиль
node tools/lab.mjs eval --script=tools/lab/census.mjs     # перепись деталей
node tools/lab.mjs eval --script=tools/lab/boardstall.mjs # компиляция шейдеров
node tools/lab.mjs eval --script=tools/lab/carry.mjs      # что реально несём
node tools/lab.mjs eval --script=tools/lab/gear.mjs       # G / V / F
node tools/lab.mjs eval --script=tools/lab/mount.mjs      # навеска модулей
node tools/lab.mjs eval --script=tools/lab/shield.mjs     # защита спавна
```

Полезные флаги: `--q=low --w=800 --h=500` (софтверный растеризатор медленный),
`--free` (движок сам крутит кадры), `--logs`, `--base=http://127.0.0.1:3000`.

**Не вызывайте `engine.step()` сотнями внутри одного `evaluate`.** Каждый шаг
рендерит мир; 300 шагов на SwiftShader — это минуты. Дожигайте таймеры напрямую
(`for (const g of gear._live) g.fuse = 0.01`).

## Главный вывод: ищите вещи, которые существуют дважды

Прошлая заметка советовала искать «мёртвые поля статов». За эту сессию тот же
класс дефекта нашёлся в геометрии, и он оказался дороже:

| что | было | где починено |
|---|---|---|
| магазин | модель строила анимированный **и** риг строил статический — два магазина на каждом оружии, в 26 мм друг от друга | `hardware/build.js` |
| прицел | 52-мм труба вварена в корпус **и** оптика приходит от рига — два прицела на планке | `models/build.js` |
| верх ресивера АК | `addUpperReceiver` фрезеровала планку Picatinny **и** билдер рисовал сверху пылезащитную крышку | `weapons/parts.js` |
| анимация слота | `unmount` начинала выезд, `mount` перезаписывала запись — старая деталь никогда не пряталась | `hardware/rig.js` |

**Как искать:** `tools/lab/census.mjs` печатает каждый меш с материалом и
габаритами в миллиметрах, отсортированный по яркости. Две записи с похожими
габаритами и разными материалами — это дубль. Так нашлись оба магазина.

## Что сделано в этой сессии

- **Загрузка.** `prewarm` получал `onProgress: null`, а `null` не подставляет
  значение по умолчанию → падение только под `?capture=1`. Все визуальные гейты
  были слепые.
- **Защита спавна.** Два окна разной длины (`player/tuning.js:spawnShield`):
  5.0 с неуязвимости и 3.2 с, пока ИИ не имеет права взять цель. Перекрытие —
  это и есть запас. Выстрел сбрасывает.
- **Пропорции оружия.** `arsenal/models/specs.js` переписан от реальных
  чертежей, в миллиметрах, с нулём в перепонке хвата. Один коэффициент `K = 0.88`
  сжимает под вид от первого лица.
- **Подписи семейств.** `arsenal/models/signature.js` — крупная геометрия,
  по которой оружие узнают: башня мушки АК, газовый блок под 45°, буферная труба
  AR, трубка взведения MP5, расколотое цевьё СВД.
- **Дерево, сталь, сливовый полимер** как разные материалы.
- **Доска не морозит игру.** `ShellSystem.prewarmMaterials()`. Замерено: 4
  программы на загрузке, 1 при открытии, 0 при закрытии.
- **Вместимость рюкзака.** `arsenal/rules.js` + `tools/verify-loadout.mjs`.
- **G / V / F.** `game/gear/index.js`.
- **Нагрев и износ.** `game/weapons/condition.js` + `tools/verify-condition.mjs`.
- **Анимация навески.** `hardware/rig.js`.

## Что НЕ сделано, по приоритету

### 1. Авторитетный сервер и лаг-компенсация — не начато

Сейчас `server/main.py` — это релей: он пересылает состояние и не решает ничего.
Клиент авторитетен по попаданиям, что для 1×1 и 10×10 неприемлемо.

Порядок работ:

1. **Вынести решение выстрела из клиента.** `weapons/index.js:tryFire` уже
   собирает всё нужное в `_firePayload` (origin, dir, seed). Пусть клиент
   отправляет *намерение*, а не результат.
2. **Кольцевой буфер позиций** на сервере: 1 с истории на актёра, шаг 50 мс.
3. **Rewind.** По `clientTime` из пакета откатить хитбоксы и провести луч.
   `physics/index.js` уже умеет `addCollider` / `setSegment` — история
   восстанавливается через них.
4. **Гейт.** `tools/verify-lagcomp.mjs`: чистая функция интерполяции истории,
   проверяемая в Node без сети.

Ключевая ловушка: `weapons/ballistics.js` — это летящие снаряды, а не хитскан.
Компенсация должна откатывать **время попадания**, а не время выстрела.

### 2. Разрушаемость — не начато

`physics/index.js` уже имеет `spawnDebris` и слои `GLASS` / `SHOOT_ONLY`, а
`world/dressing.js` расставляет пропсы. Минимальный честный шаг: у пропса
появляется `hp` и `onBreak`, который заменяет меш на обломки через `spawnDebris`.
Стены не трогать — за них держится `physics/bvh.js`, перестройка BVH в кадре
недопустима.

### 3. ПНВ — не начато

`render/index.js` уже имеет реестр пассов (`registerPass`) — ровно тот механизм,
через который включён `LowHealthPass`. ПНВ — это пасс: зелёный тонмап, усиление,
зерно, виньетка, плюс `sky.setNightVision(true)` для экспозиции. Осторожно с
`ai/index.js:_updateRelevance` — ПНВ повышает видимую дальность и меняет то,
какие агенты «видимы».

### 4. Погода — не начато

`sky/index.js` владеет атмосферой, `fx/haze.js` — дымкой. Дождь — это система
частиц плюс мокрый `roughness` в `materials/library.js` (там уже есть `weather`
в каждом рецепте, и он почти нигде не крутится динамически).

### 5. Зоны поражения — есть, но не подтверждены живьём

`ai/index.js` пишет, что у игрока есть коллайдеры головы / корпуса / ног, а
`HEALTH.bleed.zoneScale` и `ARMOUR.covers` их читают. Проба на живом матче
(`tools/lab/`) не написана — сделайте её раньше, чем будете «чинить».

## Грабли этой сессии

- **`main` в рабочем дереве отставал от `origin/main` на четыре коммита.**
  Первый коммит ушёл на устаревшую базу. Всегда `git fetch origin main` и
  `git log --oneline -3 origin/main` перед первым коммитом.

- **Гейт может тихо перестать проверять.** `verify-hardware.mjs` резал исходник
  между двумя точными *сигнатурами* методов; сигнатуры получили объект опций, и
  гейт стал измерять пустую строку и проходить по неверной причине. Если гейт
  режет исходник — проверяйте, что срез непустой.

- **Гейт может быть прав, а его предпосылка — нет.** Проверка нагрева
  утверждала, что очереди по 5 патронов с паузой в секунду обязаны греть ствол.
  Не обязаны — это ровно та доктрина, из которой взяты числа. Когда гейт красный,
  сначала спросите, верна ли посылка.

- **Числа надо выбирать парами.** `perShot` и `onset` по отдельности выглядели
  разумно и вместе делали механику недостижимой: магазин непрерывного огня давал
  множитель разброса ровно 1.00.

- **Порядок чтения состояния — это механика.** Окно «прогрева» читалось *после*
  того, как часы уже сдвинулись, поэтому один шаг в 0.8 с через 0.1 с после
  очереди списывал полную скорость охлаждения. Стрельба короткими очередями
  оказывалась термически бесплатной.

- **Свет в превью — это ключ кэша шейдеров.** Три.js кладёт число источников
  каждого типа в ключ программы. `AmbientLight` бесплатен (это юниформ, который
  и так есть у каждой освещённой программы), `HemisphereLight` — нет.
